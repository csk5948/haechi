# Haechi 해치 (Android)

외부 라이브러리 없이 순수 Java + Android 프레임워크(android.*)만으로 만든 DNS 광고 차단기입니다.
AndroidX·Kotlin·분석 도구 없음. 앱이 하는 네트워크 통신은 "허용된 DNS 질의를 DNS 서버로 전달"하는 것 하나뿐입니다
(기본: Cloudflare 암호화 DNS, 설정에서 변경 가능).

## 동작 방식

1. Android의 VpnService API로 가상 인터페이스를 만들되, **DNS 서버 주소 `10.111.222.2` 한 개만** 그 인터페이스로 라우팅합니다
   (`addRoute("10.111.222.2", 32)`). 0.0.0.0/0은 라우팅하지 않으므로 웹·영상 등 나머지 통신은 평소대로 Wi-Fi/모바일로 바로 나갑니다.
2. 시스템은 DNS 서버가 `10.111.222.2`라고 알고 있으므로 DNS 질의(UDP 53)만 앱으로 들어옵니다.
3. 질의한 도메인(또는 상위 도메인)이 차단으로 판정되면 `0.0.0.0` / `::` 응답을 앱이 직접 만들어 돌려줍니다.
   판정 순서(각 단계마다 도메인과 상위 도메인을 모두 확인): **내 허용 목록 > 내 차단 목록 > 기본 제공 목록의 예외(@@) > 기본 제공 차단 목록 > 통과**.
   그렇지 않으면 질의를 그대로 DNS 서버로 보내고 받은 응답을 돌려줍니다. 어디로 보낼지는 메인 화면의 **DNS 서버** 설정을 따릅니다(아래).
4. 기록(질의 로그)은 **메모리에만** 있습니다. 파일로 저장하지 않으며 앱 프로세스가 끝나면 사라집니다.
5. 기록 화면의 **분류** 꼬리표(광고/추적/CDN)는 함께 넣은 `assets/labels.txt`(`blocklist/labels.txt` 사본)를 따릅니다. 보기용일 뿐 차단과는 무관합니다.
   목록에 없으면 도메인을 `.`·`-`로 나눈 단어 중 ad, ads, banner… 가 있으면 `광고?`, track, analytics, log… 가 있으면 `추적?`로 추정합니다
   (단어 전체가 같아야 함 → download, address 는 해당 없음). 규칙은 `Labels.java` 주석 참고.
6. **앱 이름**(Android 10+): DNS 패킷마다 `ConnectivityManager.getConnectionOwnerUid()`로 그 질의를 보낸 소켓의 소유 앱을 시스템에 물어봅니다
   (활성 VPN 앱에만 허용되는 로컬 시스템 호출, 네트워크 통신 아님). Android가 DNS 패킷의 소유 uid를 실제 앱으로 알려 주는지에 달려 있으며,
   **실기기에서 확인하지 못했습니다.** 시스템 리졸버가 캐시한 응답은 질의가 다시 오지 않으므로 앱도 기록되지 않고,
   알 수 없거나 시스템 uid이면 "시스템"으로 표시됩니다. 앱 이름을 읽기 위해 매니페스트에 런처 앱 목록 조회(`<queries>`)를 선언했고,
   런처 아이콘이 없는 앱은 "uid 10123"처럼 보일 수 있습니다.
7. 목록 파일: 앱 전용 저장소의 `block.txt`(처음엔 비어 있음 – 광고는 기본 제공 목록이 막고, 여기엔 그 밖에 막고 싶은 것만. 예전 설치의 49개 기본 목록은 그대로 남음),
   `allow.txt`(처음엔 비어 있음), `browser.txt`(삼성 인터넷 규칙). 모두 일반 텍스트이고 백업/기기 이전 대상에서 제외됩니다.

## 기본 제공 목록 (APK 안에 포함, 업데이트 가능)

**업데이트**(목록 관리 › 기본 제공 목록 맨 위, `ListUpdater.java`): **지금 업데이트**를 누르면 세 목록을 원본 주소에서 새로 받아
`files/lists/<id>.txt`에 저장하고, 그 뒤로는 APK 안의 것 대신 그 파일을 씁니다. DNS 목록은 `tools/convert_lists.py`와 같은 규칙으로 변환합니다.
- 바뀌지 않은 목록은 ETag/Last-Modified로 확인만 하고 받지 않습니다(304).
- 받은 결과가 너무 작으면(AdGuard 5만, List-KR 50, YousList 1000 규칙 미만) 망가진 것으로 보고 이전 목록을 유지합니다.
- 바뀌면 DNS 표를 다시 읽고(필터가 켜져 있을 때) YousList는 삼성 인터넷에 업데이트를 알립니다.
- **자동으로도 업데이트**(기본 꺼짐): 켜면 JobScheduler가 하루 한 번, 와이파이·배터리 충분할 때 실행하고 마지막 성공이 3일 이상 지났을 때만 받습니다.
  재부팅 후에도 유지하려고 `RECEIVE_BOOT_COMPLETED` 권한을 씁니다.

목록:

| 목록 | 용도 | 기본 |
|---|---|---|
| AdGuard DNS (`assets/bundled/adguard-dns.txt`, 약 18만 5천 도메인) | DNS 차단 | 켬 |
| List-KR DNS (`assets/bundled/list-kr-dns.txt`, 360 도메인) | DNS 차단 | 켬 |
| YousList (`assets/bundled/youslist.txt`, Adblock Plus 규칙) | 삼성 인터넷 전용 (DNS에는 안 씀) | 켬 |

- 형식: `도메인` = 차단(하위 도메인 포함), `@@도메인` = 예외, `#` = 주석. 출처 URL과 변환 날짜는 파일 첫 줄(목록 관리 › 기본 제공 목록에 표시).
- 사용자 파일로 복사하지 않고 APK 안에서 바로 읽습니다. 켜진 DNS 목록은 필터가 켜질 때 **백그라운드에서** 하나의 표로 읽어 들이고,
  다 읽기 전까지는 내 목록만 적용됩니다. 켜고 끌 때마다 다시 읽습니다.
- 메모리: 18만 5천 개를 `HashSet<String>`으로 두면 약 19 MB(PC JVM 측정)라서, 정렬된 하나의 `byte[]` + 오프셋 배열로 두고 이진 탐색합니다(약 5 MB). `Bundled.java` 참고.
- 기본 제공 DNS 목록은 삼성 인터넷으로 넘기지 않습니다(DNS가 이미 시스템 전체에서 막음).

## 목록 관리 화면

메인 화면 **목록 관리** → 위에 **도메인 확인**(입력하면 "차단 · AdGuard DNS (doubleclick.net 규칙)"처럼 판정과 출처 표시),
탭: 차단 목록 · 허용 목록 · 브라우저 규칙 · 기본 제공 목록.

- 검색(바로 걸러짐), 개수 표시, 항목을 누르면 일시정지·재개/수정/삭제/복사, 길게 누르면 여러 개 선택 후 일시정지·재개·삭제.
- **일시정지**: 줄 오른쪽 끝 스위치(iOS식, 켜짐 = 적용)로 항목을 지우지 않고 잠시 끕니다. 파일에는 `!⏸ 원래 줄`로 남고(`!`로 시작하는 줄은 DNS 필터·삼성 인터넷·와일드카드·고르기 화면 모두 건너뜀),
  목록에는 ⏸ 표시로 보입니다. 재개하면 표시만 떼어 원래 줄로 돌아갑니다.
- **+ 추가**: 여러 줄 붙여넣기 가능. 주소를 붙여넣으면 호스트만 씁니다(`https://ad.example.com/x.jpg` → `ad.example.com`).
  차단 목록에 하나만 추가할 때는 범위(도메인/상위 도메인)를 고릅니다.
- **클립보드 주소로 차단**, 그리고 다른 앱의 **공유 → "광고 차단에 추가"**: 주소에서 호스트를 뽑아 범위를 고른 뒤 차단 목록에 추가.
- **⋯** 메뉴: 원본 텍스트로 편집, 차단 목록 비우기(처음 상태로).
- 파일은 그대로 텍스트이며, 편집은 해당 줄만 바꾸고 주석과 다른 줄은 남깁니다. 모든 변경은 즉시 필터에 반영되고 삼성 인터넷에 업데이트를 알립니다.
- 기본 제공 목록 탭: 목록별 스위치와 출처/날짜, 켜진 DNS 목록 검색(파일을 순서대로 읽어 처음 200개 표시), 결과를 눌러 "허용하기".

## DNS 서버 설정 (암호화 DNS)

| 선택 | 동작 |
|---|---|
| **Cloudflare 암호화 (1.1.1.1)** – 기본값 | DNS-over-HTTPS(RFC 8484) POST → `https://1.1.1.1/dns-query` |
| Google 암호화 (8.8.8.8) | DNS-over-HTTPS → `https://8.8.8.8/dns-query` |
| 통신사 DNS (암호화 안 함) | 현재 Wi-Fi/모바일 네트워크의 DNS 서버(없으면 1.1.1.1)로 평문 UDP 53 |

- 설정은 앱 내부 SharedPreferences에 저장되고, VPN을 다시 켜지 않아도 다음 질의부터 바로 적용됩니다.
- 주소가 숫자 IP라서 DoH 서버를 찾기 위한 DNS 조회가 없고(두 인증서 모두 IP를 포함), 연결은 VPN이 아닌 실제 네트워크에 묶어서
  (`Network.openConnection`) 엽니다. 질의 ID는 0으로 보내고(RFC 8484 권장) 응답에서 원래 ID로 되돌립니다. 연결/읽기 타임아웃 4초, 연결은 재사용(keep-alive).
- 암호화 DNS가 실패하면(네트워크/HTTP 오류) 그 질의만 통신사 DNS로 보내서 인터넷은 계속 되게 하고, 메인 화면에
  "암호화 DNS 실패 → 통신사 DNS 사용 N회"를 표시합니다. 이때 그 질의는 통신사가 볼 수 있고 조작될 수도 있습니다.
- **개인정보 트레이드오프**: 암호화 DNS를 쓰면 통신사가 DNS 응답을 조작하거나(warning.or.kr로 돌리기) 엿볼 수 없습니다.
  대신 어떤 도메인에 접속하는지는 선택한 회사(Cloudflare 또는 Google)가 보게 됩니다.
- **한계**: warning.or.kr 차단 중 **SNI 필터링**(접속 시 TLS의 서버 이름을 보고 연결을 끊는 방식 – 경고 페이지 대신 "연결이 재설정됨")은
  DNS와 무관하므로 이 설정으로 해결되지 않습니다. 해결되는 것은 DNS 응답을 바꿔치기하는 방식뿐입니다.

## SNI 쪼개기 (브라우저용 로컬 프록시, 선택)

SNI 필터링(TLS 첫 패킷의 사이트 이름을 보고 연결을 끊는 방식)을 피하기 위한 기능입니다. 메인 화면 스위치, **기본 꺼짐**, Android 10+.

- 켜고 VPN을 시작하면 `VpnService.Builder.setHttpProxy(127.0.0.1:임의포트)`로 시스템 HTTP 프록시를 지정합니다. 프록시 설정을 따르는 앱
  (크롬, 삼성 인터넷 등)의 HTTP/HTTPS가 앱 안의 `SplitProxy.java`로 들어옵니다. 스위치를 바꾸면 켜져 있는 해치가 알아서 다시 시작(끄기 → 0.8초 → 켜기)해 적용합니다.
- HTTPS(`CONNECT`): 사이트에 연결한 뒤 200을 주고, 브라우저가 보내는 첫 TLS 레코드(ClientHello)를 **사이트 이름 한가운데에서 둘로 나눠
  별개의 TCP 세그먼트 두 개로** 보냅니다(`TCP_NODELAY`). 첫 세그먼트만 보는 필터는 이름 전체를 못 봅니다. 이후는 그대로 전달만 하고,
  암호를 풀지 않으며 인증서도 필요 없습니다. TLS가 아니면 손대지 않습니다. 일반 HTTP는 요청줄만 고쳐 전달합니다.
- 사이트 이름은 시스템 리졸버(= 이 앱의 DNS 필터)로 찾으므로 차단 목록의 도메인(0.0.0.0 응답)은 중계기에서도 403으로 거절합니다.
  DNS 설정(암호화 DNS)도 그대로 적용됩니다.
- 한계: 프록시를 무시하는 앱은 거치지 않습니다. 필터가 TCP 재조립까지 하는 장비면 효과가 없습니다. QUIC(HTTP/3, UDP)은 프록시를 못 지나므로
  브라우저가 HTTPS(TCP)로 접속할 때만 해당합니다. **실기기에서 확인하지 못했습니다.**
- 네트워크 코드는 `SplitProxy.java`에 있고, 외부로 나가는 연결은 브라우저가 요청한 사이트로의 연결뿐입니다.

## HTTPS 필터링 (CA 인증서, 선택)

메인 화면 **HTTPS 필터링** 스위치, **기본 꺼짐**, Android 10+. 같은 중계기(위 SNI 쪼개기와 같은 127.0.0.1 프록시)를 쓰며,
둘 중 하나라도 켜면 중계기가 뜹니다. 스위치를 바꾸면 켜져 있는 해치가 알아서 다시 시작(끄기 → 0.8초 → 켜기)해 적용합니다.

- **인증서**(`CertAuthority.java`): **인증서 만들기·저장**을 누르면 RSA 2048 CA 열쇠를 **Android Keystore 안에서** 만듭니다
  (꺼낼 수 없는 열쇠, 서명은 보안 영역(TEE) 안에서만). 해치·`run-as`·백업 어느 쪽으로도 열쇠는 읽히지 않고, 인증서(공개 부분)만
  `files/ca/ca.der`와 다운로드 폴더의 `haechi-ca.crt`로 저장합니다. StrongBox(별도 보안 칩)는 서명이 느려(새 사이트마다 한 번) 쓰지 않습니다.
  예전 빌드(0.13)가 파일(`files/ca/ca.key`)로 둔 열쇠는 계속 쓰되, 화면에 **인증서 새로 만들기**를 권하는 경고를 띄웁니다.
  해치를 지우거나 앱 데이터를 지우면 열쇠도 사라지므로, 그때는 인증서를 새로 만들어 다시 설치해야 합니다.
  BouncyCastle 없이 X.509 v3 DER을 직접 쓰고(SHA256withRSA), 사이트마다 그 이름(SAN)의 1년짜리 인증서를 만들어 기억합니다(300개).
- **설치**: 설정 › 보안 › (기타 보안 설정 ›) 암호화 및 사용자 인증 정보 › 인증서 설치 › **CA 인증서** → `haechi-ca.crt`.
  Android 11부터는 앱이 바로 설치시킬 수 없어 **설치 화면** 버튼은 보안 설정을 엽니다(Android 10은 설치 창이 바로 뜸).
  설치 여부는 시스템 CA 저장소(`AndroidCAStore`)에서 확인하고, 설치 안 됐으면 켜 두어도 풀지 않습니다.
- **동작**(`HttpsFilter.java`): 브라우저의 `CONNECT 사이트:443`을 받으면 먼저 진짜 사이트와 TLS로 연결해 폰의 기본 신뢰 저장소로
  인증서·이름을 확인하고(실패하면 손대지 않고 원래대로 중계 → 브라우저가 진짜 오류를 봄), 브라우저에는 해치 CA가 서명한 인증서로 TLS를 엽니다.
  ALPN을 알리지 않아 HTTP/1.1로 오가고, 그 사이에서:
  - **요청 차단**(`AdRules.java`): 브라우저 규칙 + 켜진 팩 + YousList(켜져 있으면) + 내 차단/허용 목록의 주소 규칙.
    `||호스트/경로^`, `*/경로/*`, `|https://…|`, `@@` 예외, `$domain=`, `$third-party`/`$first-party`, 요청 종류(script, image, …;
    크롬의 `Sec-Fetch-Dest`로 앎). 그 밖의 옵션(`$csp`, `$redirect`, `$popup` …)이 붙은 규칙과 정규식 규칙은 건너뜁니다.
    페이지 자체는 막지 않고, 막은 요청은 204(프레임은 빈 페이지)로 답합니다. DNS로는 못 막는 "같은 도메인의 광고 경로"도 막힙니다
    (예: `zicf.inven.co.kr/RealMedia/ads/…`).
  - **요소 숨김**: 페이지(HTML)에 그 사이트의 `##` 규칙을 `<style>`로 `<head>` 바로 뒤에 넣습니다(선택자마다 한 줄이라 잘못된 선택자는
    그 줄만 무시됨). 페이지 요청에만 `Accept-Encoding: gzip, deflate`로 바꿔 압축을 풀고 다시 chunked로 보냅니다.
    `#@#` 예외와 `$elemhide`/`$generichide`/`$document` 예외를 따르고, 확장 문법(`:has-text` 등)은 건너뜁니다.
    Content-Security-Policy가 인라인 스타일을 막는 사이트는 그 정책에 우리 스타일의 해시(`'sha256-…'`)를 더합니다.
  - **내용 고치기**(`$replace`, AdGuard와 같은 문법): `||주소$replace=/정규식/바꿀 말/플래그`. 주소가 맞는 응답(페이지·JSON·스크립트·XML,
    gzip/deflate까지)을 통째로 받아 압축을 풀고 정규식으로 고친 뒤 보냅니다. 광고가 본문과 같은 응답 안에 섞여 와서 주소로는
    못 나누는 경우용입니다(유튜브의 `adPlacements`). 플래그 `g` = 전부, `i` = 대소문자 무시, 바꿀 말의 `$1` = 묶은 부분,
    값 안의 `/`·`,`는 `\/`·`\,`로 씁니다. `@@주소$replace`는 그 주소의 고치기를 끕니다. 16MB가 넘는 응답은 고치지 않고 그대로 보냅니다.
    삼성 인터넷에는 전달하지 않습니다. 요청 기록에 "N곳 고침", "고칠 곳 없음"(규칙은 걸렸지만 패턴이 없음),
    "못 고침 (상태 · 종류 · 압축)"이 남아 패턴을 맞출 때 참고할 수 있습니다.
  - 기본 팩 `youtube-ads-https.txt` "유튜브 광고 일정 지우기 (HTTPS 필터링)"(꺼진 채로 추가): youtubei API의 JSON과 영상 페이지 HTML 안의
    `"adPlacements"`·`"playerAds"`·`"adSlots"`를 `"no_ads"`로 바꿔 플레이어가 광고 일정을 모르게 합니다. 에뮬레이터 크롬의
    m.youtube.com 영상 페이지에서 켜기 전 `adPlacements` 있음 → 켠 뒤 없음(`no_ads`)을 확인했습니다. 실제로 광고가 안 나오는지는
    에뮬레이터에 광고가 나오지 않아 확인하지 못했습니다. 유튜브 앱, 영상 안에 붙여 보내는 광고(서버 삽입)에는 효과가 없습니다.
  - 그 밖의 요청·응답, WebSocket(101)은 그대로 전달합니다.
- **풀지 않는 연결**: 443 이외 포트, IP 주소, 허용 목록 도메인, 브라우저가 아닌 앱. 연결한 앱은 `getConnectionOwnerUid()`로 확인해
  크롬·삼성 인터넷·엣지·브레이브·웨일 등과 해치 자신(고르기 화면)만 풉니다. 다른 앱은 대부분 사용자 CA를 믿지 않아 깨지므로 그대로 통과시킵니다.
  앱을 알 수 없을 때는 풀어 보고, TLS가 거부된 사이트는 기억해 다음부터 그대로 통과시킵니다(필터를 다시 켜면 초기화).
- 고르기 화면(WebView)은 앱 자체가 사용자 CA를 믿지 않으므로, `onReceivedSslError`에서 **해치 CA가 서명했고 이름이 맞는 인증서만** 받아들입니다.
- 메인 화면에 푼 연결·막은 요청·숨김 넣은 페이지·그냥 통과한 수.
- **요청 기록 (HTTPS)** 메뉴(`RequestLogActivity.java`, `RequestLog.java`, DNS 기록과 별개): 푼 연결 안의 요청을 전체 주소로 봅니다
  (종류, 요청한 페이지, 막음/통과/숨김 넣음, 막은 규칙, HTTP 상태). **처음엔 꺼져 있고** '● 녹화 시작'을 눌러야 기록합니다(페이지 하나에
  요청이 수백 개라서). 메모리에만 최근 1,500개, 앱이 끝나면 사라집니다. 주소에 검색어·토큰이 들어 있을 수 있어 파일로 남기지 않습니다.
  검색칸은 주소를 찾고, 옆의 **내용 찾기**는 보관된 모든 응답의 내용에서 그 글자를 찾아(대소문자 무시) 든 요청에 📄를 붙여 보여 줍니다
  (예: `adPlacements` → 유튜브 영상 페이지). 그 줄의 응답 내용을 열면 같은 글자로 바로 찾아 둡니다.
  막은 것만/통과만/다른 사이트 것만/광고·추적 의심만 거르기, 그리고 함께 쓰는 **응답 내용이 보관된 것만** 토글.
  **빠지는 요청**: 크롬은 한 번 받은 스크립트·스타일·이미지를 캐시에 두고 다시 묻지 않아 해치까지 오지 않습니다(에뮬레이터 인벤 새로고침:
  요청 208개 중 네트워크 30, 디스크 캐시 43, 메모리 캐시 114). 그래서 **녹화 중엔 브라우저 캐시 안 쓰게 하기**(기본 켬)가 녹화 중 응답에
  `Cache-Control: no-store`를 붙이고 `ETag`·`Last-Modified`·`Expires`를 빼며, 요청의 `If-None-Match`·`If-Modified-Since`를 지워
  304 대신 전체 응답을 받습니다. 이미 캐시에 든 것은 크롬 설정 › 인터넷 사용 기록 삭제 › '캐시된 이미지 및 파일'을 한 번 지우고
  탭을 새로 열어야 보입니다(새로고침은 탭의 메모리 캐시를 다시 씀).
  **풀지 않음** 줄: 녹화 중 해치가 열지 않고 그대로 넘긴 연결(443 아닌 포트, IP 주소, 허용 목록, 브라우저가 아닌 앱(앱 이름),
  사이트 인증서 확인 실패, 해치 인증서를 거부한 브라우저/앱)도 이유와 함께 남습니다. 그 안의 요청은 볼 수 없습니다. 줄을 누르면 `||호스트/경로^`, `||호스트/폴더/`, `||호스트^`,
  `||사이트^`(하위 호스트 전부) 막기 또는 막힌 것의 `@@` 허용 규칙을 고쳐서 브라우저 규칙에 추가합니다. "이 사이트에서 열린 것만"을
  고르면 `$domain=`이 붙습니다. 브라우저 규칙이라 삼성 인터넷에도 함께 적용됩니다.
- **응답 내용 보기**(`BodyActivity.java`): 녹화 중에는 글자로 된 응답(페이지·JSON·스크립트·스타일·XML)을 받은 그대로(대개 gzip) 보관합니다.
  응답 하나에 앞 4MB, 모두 합쳐 32MB까지이고 넘으면 오래된 것부터 지웁니다. 녹화 중에는 풀 수 있게 요청의 압축을 gzip/deflate로 바꿉니다
  (brotli 안 씀). 요청 기록에서 줄을 누르면 **응답 내용 보기**:
  압축을 푼 원문(해치가 고치기 전), 앞 10만 자 표시, **찾기**(글자 또는 정규식)로 걸린 곳마다 앞뒤 120자와 노란 표시, 누르면 앞뒤
  1,500자에서 글자를 골라 규칙으로. **지우기 규칙 만들기** = 주소·찾을 것(정규식, 고른 글자는 자동 이스케이프)·바꿀 말(비우면 지움)·
  모두 바꾸기를 고치고 "이 응답에서 N곳이 걸립니다"를 보며 `$replace` 규칙을 브라우저 규칙에 추가합니다. 요청·응답 **머리글**도 볼 수 있고
  쿠키·로그인 값(Cookie, Set-Cookie, Authorization)은 남기지 않습니다. 모두 메모리에만 있습니다.
  에뮬레이터에서 example.com 원문을 보고 "domain"을 찾아 `HAECHI`로 바꾸는 규칙을 만든 뒤, 다시 연 페이지 문장이 바뀐 것을 확인했습니다.
- **인증서 새로 만들기**: 이전 CA를 지우고 새로 만듭니다. 폰에 설치된 예전 인증서는 설정 › 사용자 인증서에서 직접 지워야 합니다.
- 한계: 사용자 CA를 믿는 브라우저만 됩니다(파이어폭스는 기본으로 안 믿음). HTTP/1.1이라 HTTP/2보다 연결이 많아집니다.
  클라이언트 인증서를 요구하는 사이트는 안 됩니다(허용 목록에 넣으면 풀지 않음). 일반 HTTP(암호화 안 된) 요청에는 적용하지 않습니다.
- 에뮬레이터(Android 16, 크롬)에서 example.com·GitHub(엄격한 CSP)·인벤·디시인사이드 접속, 요청 차단, 숨김 적용, 고르기 화면을 확인했습니다.
  실기기와 삼성 인터넷에서는 확인하지 못했습니다.

## 삼성 인터넷 광고 차단기 (요소 숨김 규칙)

인증서(CA)나 다른 앱 없이, 이 앱이 삼성 인터넷의 "광고 차단기"로도 동작합니다
([Samsung Ad Blockers 가이드](https://developer.samsung.com/internet/android/adblockers-guide.html)).

- **목록 관리 › 브라우저 규칙** → `browser.txt` 편집 (Adblock Plus 형식).
  `도메인##CSS선택자` = 그 사이트에서 요소 숨김, `||도메인^` = 요청 차단, `@@||도메인^` = 예외, `!` = 주석.
  처음엔 시험용 `example.com##p`(문단 숨기기; 예전 `example.com##h1`은 페이지에 h1이 없어져 자동으로 바꿈)와 주석 처리된 `namu.wiki##.powerlink` 예시(실제 클래스 이름 모름 – 나무위키는 클래스 이름을 난독화)가 들어 있습니다.
- 삼성 인터넷에 넘기는 내용 = `[Adblock Plus 2.0]` + `browser.txt` + YousList(켜져 있으면) + 내 차단 목록을 `||도메인^`으로 바꾼 것
  (허용 목록에 걸리는 도메인은 제외) + 허용 목록을 `@@||도메인^` 예외로. 기본 제공 DNS 목록은 넣지 않습니다.
- 전달 방식: `ContentBlockerProvider.java`(authority `local.haechi.contentBlocker.contentProvider`)의 `openFile()`이 이 목록을 읽기 전용 파일로 돌려줍니다.
  삼성 인터넷 패키지(`com.sec.android.app.sbrowser*`)만 읽을 수 있습니다. 앱 사이 전달일 뿐 네트워크 통신은 없습니다.
- 목록을 저장할 때마다 `com.samsung.android.sbrowser.contentBlocker.ACTION_UPDATE` 브로드캐스트로 삼성 인터넷에 새로 읽으라고 알립니다.

### 광고 요소 골라 숨기기 (앱 안 브라우저)

메인 화면 **광고 요소 골라 숨기기**, 목록 관리 › 브라우저 규칙 › **페이지에서 고르기**, 또는 삼성 인터넷에서
**공유 → "광고 요소 숨기기"** 로 엽니다(`PickerActivity.java`, `assets/picker.js`).

1. 앱 안 브라우저(WebView)에서 페이지를 엽니다. browser.txt 에 이미 있는 이 사이트의 `##` 규칙은 미리 적용해서 보여 줍니다.
2. **● 요소 고르기** → 광고를 누르면 빨갛게 표시되고 CSS 선택자가 만들어집니다. 고르는 동안 링크는 열리지 않고 스크롤은 됩니다.
   투명한 막이 터치를 받으므로 iframe 광고도 iframe 째로 골라집니다.
3. **▲ 넓게 / ▼ 좁게**로 감싼 상자까지 넓히거나 되돌립니다. 선택자는 손으로 고칠 수 있고 "일치 N개"가 바로 바뀝니다.
   - **클래스 이름으로**: `태그.클래스` 경로 중 같은 요소들을 고르는 가장 짧은 꼬리. 숫자가 3개 이상 이어진 이름은 무작위로 보고 뺍니다.
   - **구조로**: 클래스를 무시하고 `태그:nth-of-type(n)` 경로 (나무위키처럼 클래스 이름을 매번 바꾸는 사이트용, 대신 구조가 바뀌면 깨짐).
4. **미리 숨기기**로 확인 → **규칙 추가** = `사이트##선택자`(체크 해제 시 `##선택자`, 모든 사이트)를 browser.txt 끝에 추가하고 삼성 인터넷에 알립니다.

- 제목줄 왼쪽 **←** = 고르기 화면 바로 닫기.
- 주소창 옆 **◀ ▶ ⟳** = 이전·다음 페이지, 새로고침. 폰의 뒤로 버튼도 이전 페이지로 가고, 첫 페이지에서는
  고르는 중이면 고르기만 끄며, 아니면 "한 번 더 누르면 닫힙니다" 후 2초 안에 다시 눌러야 화면이 닫힙니다.
- **숨기기 / 남기기 토글**: 토글은 "다음에 누르는 것이 무엇인지"만 정하고, 바꿔도 이미 고른 것은 그대로입니다(자동 전환 없음).
  숨기기 = 숨길 **영역**(▲▼로 크기 조절), 남기기 = **남길 것**(초록, 여러 개, 다시 누르면 취소, ▲▼는 마지막 것의 크기).
  영역 안에 남길 것이 없으면 영역 통째로 한 줄, 있으면 영역 안에서 남길 것과 그리로 가는 길이 아닌 요소만 숨기는 규칙을 한 줄씩 만듭니다.
  영역 밖의 남길 표시는 무시합니다. `:has()` 없이 기본 숨김 문법만 쓰고, 각 선택자가 영역 안에만 걸리고 남길 것에 걸리지 않는지 확인합니다.
  한계: 영역의 배경·여백은 남고, 사이트가 나중에 새 칸을 넣으면 그건 안 숨겨집니다.
- **SNI 쪼개기**를 켜 두면 고르기 화면의 브라우저도 중계기를 거칩니다. 화면을 열 때 해치 프로세스를 프록시가 걸린 VPN 네트워크에
  묶어서(`bindProcessToNetwork`) WebView가 그 프록시를 읽게 하고, 닫을 때 풉니다. 아래 안내 줄에 "SNI 쪼개기 적용 중/안 됨"이 나옵니다.
  필터를 켜기 전에 연 화면은 적용이 안 되니 닫았다 다시 여세요.
- **사이트** 칸: 처음엔 지금 사이트, 비우면 모든 사이트(`##선택자`). **숫자 → \*** 는 `aa12.com` → `aa*.com`.
- 사이트가 삼성 인터넷과 같은 화면을 주도록 사용자 에이전트를 삼성 인터넷처럼 바꿉니다(`; wv` 제거, `SamsungBrowser/27.0` 추가).
  그래도 로그인 상태·광고 종류가 달라 구조가 다를 수 있습니다.
- http/https 외의 주소(intent:, market: …)는 열지 않습니다. 파일 접근 꺼짐.
- 페이지 스크립트도 `HaechiPicker` 인터페이스를 부를 수 있지만, 하는 일은 선택자 칸을 채우는 것뿐이고 추가는 사용자가 눌러야 합니다.

### 팩 (규칙 묶음)

목록 관리 › **팩** 탭(`Packs.java`). 팩 = 이름 붙은 브라우저 규칙 묶음으로, `files/packs/<id>.txt` 한 파일에 browser.txt와 같은 형식으로 들어갑니다.
첫 줄 `! 팩: 이름`이 이름이라 파일을 텍스트로 공유해도 이름이 따라갑니다.

- 팩마다 **스위치**로 통째로 켜고 끔(설정 `packs.xml`). 켜진 팩만 삼성 인터넷·고르기 화면 미리보기·와일드카드 감시에 들어갑니다.
- 팩을 누르면 안의 규칙 목록: 항목별 켜기/끄기 스위치, 추가·수정·삭제, ⋯ 메뉴에 이름 바꾸기·공유하기(텍스트)·팩 삭제·원본 텍스트로 편집.
- **+ 새 팩**, 브라우저 규칙(또는 다른 팩)에서 여러 개를 길게 눌러 골라 **팩으로** 옮기기(팩에서 브라우저 규칙으로 되돌리기도 가능).
- 고르기 화면 **저장할 곳**: 브라우저 규칙 / 각 팩 / 새 팩. 팩 안에서 "골라 숨기기"로 열면 그 팩이 기본입니다.
- 기본 팩: `assets/packs/youtube.txt` "유튜브 (모바일 웹)" — 쇼츠 탭·쇼츠 묶음, 영상 아래 추천, 댓글, 광고 칸. 처음 한 번만 복사되고 **꺼진 채**로 시작하며,
  지우면 다시 생기지 않습니다. 2026-10-17 에뮬레이터 크롬의 m.youtube.com에서 요소 이름을 확인해 만들었습니다(재생 전 광고는 숨기기로 못 없앰).
- 기본 팩: `assets/packs/naver.txt` "네이버 메인 검색창만" — m.naver.com 첫 화면에서 광고 배너(`#HOME_AD`)·메뉴 줄·피드·유도 배너·하단을 숨겨
  검색창만 남김. 옆으로 넘기는 다른 판과 검색 결과는 그대로. 새 기본 팩은 앱을 업데이트하면 꺼진 채로 추가됩니다.
- 기본 팩: `assets/packs/naver-clip.txt` "네이버 검색: 클립 빼기" — 검색 결과의 '네이버 클립' 묶음 칸, 인물 정보 상자 영상 줄에 섞인 클립 항목,
  검색 탭의 '클립' 탭. 클래스 이름은 무작위라 `data-template-id="clipItem"`, `data-service-type="CLIP"` 같은 속성으로 찾습니다.
- 기본 팩: `naver-search-ads.txt` "네이버 검색: 광고·쇼핑 빼기" — 광고 서버(`ader.naver.com`) 링크가 든 결과 상자(파워링크, 브랜드 검색·콘텐츠,
  관련 광고, 쇼핑 광고)와 쇼핑 묶음(`#shp_*`, `#shs_*`). '노트북', '강아지사료' 검색으로 확인.
- 기본 팩: `news-comments.txt` "뉴스 댓글 숨기기" — 네이버 뉴스(`div.cbox_wrapper`)·다음 뉴스(`div.comment_view`) 댓글과 댓글 수 버튼.
  '많이 본 뉴스' 피드 줄은 일시정지(`!⏸`)된 채로 들어 있어 원하면 켭니다.
- 기본 팩: `coupang.txt` "쿠팡: 광고 상품·앱 유도 빼기" — 검색 결과의 AD 상품(광고 정보 버튼·광고 링크), 위쪽 광고 배너, 앱 유도 팝업.
- 기본 팩은 처음 한 번만 복사되므로, 이미 받은 팩의 내용이 바뀌어도 자동으로 고쳐지지 않습니다(바뀐 내용은 새 팩으로 내보냄).

**쓰는 법 안내**(`GuideActivity.java`): 목록 관리 › 브라우저 규칙의 **?**, 고르기 화면의 **?**, 원본 편집의 **쓰는 법** 버튼.
사이트 쓰는 법, 클래스·id, 이름 일부(`[class^="ad-"]`), 구조(`>`, `:nth-of-type`, `:has`), 요청 차단·예외를 예시로 보여 주고, 예시를 누르면 복사됩니다.

### 미러 사이트 와일드카드 (`aa*.com##선택자`)

이름의 숫자만 바뀌는 미러 사이트(aa1.com, aa2.com …)를 규칙 하나로 잡습니다(`Wildcards.java`).
`*` = 글자·숫자·`-` 아무거나 0개 이상(점은 아님). `,`로 여러 개, `~aa9.com` 제외도 됩니다.

- Adblock Plus 형식(삼성 인터넷)에는 이런 문법이 없어서 해치가 풀어서 넘깁니다. 필터가 켜진 동안 모든 DNS 질의를 패턴과 비교해
  맞는 도메인(`www.aa7.com` → `aa7.com`)을 `wildcard_seen.txt`에 기억하고(최대 2000개), 새로 찾을 때마다 삼성 인터넷에 업데이트를 알립니다.
  고르기 화면에서 연 페이지도 기억합니다(필터가 꺼져 있어도).
- 삼성 인터넷에는 `aa1.com,aa2.com,aa7.com##선택자`로 갑니다. 아직 찾은 도메인이 없으면 그 줄은 **보내지 않습니다**
  (사이트 없이 보내면 모든 사이트에 적용되므로). 제외(`~`)한 도메인은 포함 쪽에서 뺍니다.
- 한계: 새 미러는 처음 접속할 때 DNS로 알게 되므로 첫 화면엔 안 가려질 수 있고, 삼성 인터넷이 규칙을 다시 읽은 뒤(새로고침) 가려집니다.
  삼성 인터넷의 자체 "보안 DNS"를 켜면 질의가 해치를 거치지 않아 새 미러를 못 찾습니다.
- 목록 관리 › 브라우저 규칙 › **⋯ › 와일드카드(\*)로 찾은 도메인**에서 보기/모두 지우기.

**연동 방법** (스토어 등록 안 된 앱이라 개발자 모드가 필요):
1. 삼성 인터넷 주소창에 `internet://contentblock` 입력 → 개발자 모드 켜기
2. 삼성 인터넷 설정 › 광고 차단기 에서 '광고 차단' 켜기
3. example.com 에서 글이 사라지고 아이콘만 남으면 요소 숨김이 동작하는 것

주의: 삼성 가이드는 Adblock Plus 형식이라고만 하고, `##` 요소 숨김을 지원하는지는 **문서에 없습니다**. 실기기에서 확인하지 못했습니다.

## 권한과 이유

| 권한 | 이유 |
|---|---|
| `INTERNET` | 허용된 DNS 질의를 DNS 서버로 전달 (암호화 DNS의 HTTPS 연결, 또는 통신사 DNS로 가는 UDP 소켓) |
| `ACCESS_NETWORK_STATE` | 현재 Wi-Fi/모바일 네트워크의 DNS 서버 주소 읽기, 네트워크 변경 감지 |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | 화면을 꺼도 필터가 계속 동작하도록 알림과 함께 실행 (Android 14+는 유형 명시 필요) |
| `POST_NOTIFICATIONS` | Android 13+에서 "광고 차단 중 · N개 차단" 알림 표시 |
| `RECEIVE_BOOT_COMPLETED` | 목록 자동 업데이트(켰을 때만)의 예약이 재부팅 뒤에도 남도록 |
| `BIND_VPN_SERVICE` (서비스 보호용) | 시스템만 VPN 서비스에 연결할 수 있게 함. 앱이 요청하는 권한이 아님 |
| `BIND_QUICK_SETTINGS_TILE` (서비스 보호용) | 시스템만 빠른 설정 타일에 연결할 수 있게 함 |
| `com.samsung.android.sbrowser.permission.CONTENTBLOCKER` | 삼성 가이드가 요구하는 광고 차단기 표시용 권한 |
| `<queries>` (삼성 인터넷, 런처 앱) | 삼성 인터넷에 업데이트 알림/설정 열기, 기록 화면에 앱 이름 표시. 다른 앱의 데이터 접근 권한은 아님 |

## 네트워크 호출 위치

모든 통신은 `forward()` 한 곳에서 시작합니다 (`app/src/main/java/local/haechi/BlockerService.java:253`).

- 암호화 DNS: `BlockerService.java:261` → `Doh.java:29` `exchange()` – HTTPS POST. `Doh.java:45` 요청 본문 전송, `Doh.java:54` 응답 수신
- 통신사 DNS(선택했거나 암호화 DNS 실패 시): `BlockerService.java:271` UDP send, `:274` receive (UDP 53, 3초 타임아웃, `protect()` 적용)
- `BlockerService.java:336` `refreshUpstream()` – 통신 없음. 시스템에 DNS 서버 주소와 실제 네트워크만 물어봄. 1.1.1.1은 숫자 IP라 조회도 하지 않음
- `BlockerService.java:289` `attribute()` – 통신 없음. 시스템에 "이 소켓의 앱이 누구인가"만 물어봄

- `SplitProxy.java`, `HttpsFilter.java` – 중계기(SNI 쪼개기·HTTPS 필터링을 켰을 때만). 브라우저가 요청한 사이트로만 연결합니다.
  HTTPS 필터링 중에는 브라우저의 요청을 그 사이트로 그대로 보내며, 바꾸는 것은 페이지 요청의 `Accept-Encoding`뿐입니다.
- `PickerActivity.java` – 앱 안 브라우저(WebView)가 사용자가 연 페이지를 불러옵니다. 고른 선택자는 밖으로 보내지 않습니다.
- `ListUpdater.java` `fetch()` – 기본 제공 목록 업데이트. "지금 업데이트"를 누를 때, 또는 자동 업데이트를 켰을 때만(기본 꺼짐)
  아래 세 원본 주소로 HTTPS GET. 보내는 것은 요청과 `If-None-Match`/`If-Modified-Since`(받은 목록이 바뀌었는지 묻는 값)뿐입니다.

그 외 파일(`Dns.java`, `Lists.java`, `Bundled.java`, `Domains.java`, `Labels.java`, `QueryLog.java`, `Settings.java`,
`SamsungBlocker.java`, `ContentBlockerProvider.java`, 화면들)에는 네트워크 코드가 없습니다.

## 사용

- 앱에서 **켜기** → VPN 연결 허용.
- **빠른 설정 타일**: 상단 알림창을 내려 빠른 설정 패널 편집(연필 아이콘) → '광고 차단'을 끌어다 놓기. 탭하면 켜기/끄기, 길게 누르면 해치 앱이 열림.
- **기록**: "● 새로 녹화" 후 앱을 쓰고 "■ 정지"하면 그 사이 접속한 도메인을 볼 수 있음. 도메인을 누르면 차단/허용/취소.
- 개인 DNS(설정 > 네트워크)는 **끄기** 또는 **자동**이어야 합니다. 호스트 이름을 지정하면 DNS가 앱을 거치지 않습니다.
  (DNS 암호화가 목적이라면 개인 DNS 대신 이 앱의 "DNS 서버" 설정을 쓰세요.)
- **업데이트 후 자동 재시작**: 새 버전을 설치하면 Android가 앱을 끝내 필터도 꺼지지만, 켜져 있었다면 `UpdateReceiver`가 `MY_PACKAGE_REPLACED`를 받아 다시 켭니다.
  "끄기"로 직접 껐거나 다른 VPN이 자리를 가져갔으면 켜지 않습니다(설정 `want_on`).
- 부팅 시 자동 시작: 설정 > 네트워크 > VPN > 이 앱 > '상시 사용 VPN'.
- **해치에서 뺄 앱**(메인 화면 메뉴): 체크한 앱은 `addDisallowedApplication`으로 VPN 밖에 둡니다. 그 앱의 DNS는 걸러지지 않고
  SNI 쪼개기 프록시도 적용되지 않습니다. 결제·은행 앱처럼 차단이나 프록시 때문에 안 되는 앱용. 기본으로 삼성 월렛(삼성페이)과
  그 프레임워크·미니·워치 플러그인, 삼성 패스가 체크되어 있습니다(`BlockerService.DEFAULT_EXCLUDED`).
  VPN을 시작할 때 읽으므로, 켜져 있을 때 바꾸면 화면을 나갈 때 필터를 다시 시작합니다.
- 한계: 광고가 본문과 같은 도메인에서 오면(예: YouTube) DNS로는 막을 수 없습니다. 열쇠 아이콘은 VPN API를 쓰기 때문에 표시됩니다.

## 빌드

JDK 17, Android SDK(platform 35) 필요. `local.properties`에 `sdk.dir` 지정.

```
cd haechi\android
set JAVA_HOME=C:\Program Files\Java\jdk-17
gradlew.bat assembleRelease
```

결과: `app\build\outputs\apk\release\app-release.apk`. 배포는 릴리스 빌드로 합니다. 디버그 빌드는 USB 디버깅으로
`run-as` 해 앱 파일을 꺼낼 수 있기 때문입니다(개발 중에는 `assembleDebug`).

**서명 키**: `android/keystore.properties`(`storeFile`, `storePassword`, `keyAlias`, `keyPassword`)와 거기 적힌 `.jks`.
둘 다 git에서 제외돼 있으니 **따로 백업**하세요. 키를 잃으면 업데이트를 덮어 설치할 수 없어 앱을 지워야 하고, 그러면 CA 열쇠도 사라집니다.
파일이 없으면 릴리스 APK는 서명되지 않습니다. 빌드 도구(Android Gradle Plugin)만 받으며 APK에는 이 저장소의 코드만 들어갑니다.
