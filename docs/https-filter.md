# 해치 HTTPS 필터 기획서

> 2026-10-18 · 상태: 기획 확정, 1단계부터 구현 시작

## 목표

- 브라우저(크롬, 삼성 인터넷 등) HTTPS 통신을 해치가 폰 안에서 풀어서
  - **해치 규칙(브라우저 규칙, 팩)을 모든 브라우저에 적용**
  - **유튜브 영상 광고처럼 데이터로 오는 광고를 제거**
  - 삼성 인터넷 개발자 모드·검증 없이 동작
- 기존 기능(DNS 차단, SNI 쪼개기, 삼성 인터넷 연동)은 그대로 두고, HTTPS 필터는 **선택 기능(기본 꺼짐)**.

## 동작 구조

```
브라우저 ──(프록시 127.0.0.1)──> 해치 중계기 ──> 실제 사이트
                                  │
                                  ├─ 풀지 않을 사이트: 지금처럼 그대로 통과 (SNI 쪼개기만)
                                  └─ 풀 사이트: 해치 인증서로 TLS 종료 → 페이지 고치기 → 실제 사이트로 TLS 재접속
```

- 기존 `SplitProxy`(SNI 쪼개기 중계기)를 확장. VPN의 HTTP 프록시 설정으로 브라우저 통신이 들어옴.
- 브라우저 쪽은 HTTP/1.1만 협상(ALPN `http/1.1`) → 요청·응답을 그대로 읽고 고칠 수 있음.
- 사이트 쪽 요청은 `Accept-Encoding: gzip`으로 바꿔서 압축을 풀 수 있게(외부 라이브러리 없이 `java.util.zip`).

## 무엇을 풀까 (범위)

| 구분 | 사이트 | 처리 |
|---|---|---|
| 풀기 | 켜진 브라우저 규칙·팩에 나오는 사이트, 유튜브 | 규칙 적용 |
| **절대 안 풀기** | 은행·증권·카드·결제·정부·의료 (기본 목록 + 사용자 추가) | 그대로 통과 |
| 풀었다가 실패 | 인증서 고정 등으로 접속이 깨지는 사이트 | 자동으로 "안 풀기"에 넣고 통과 |
| 나머지 | 규칙 없는 사이트 | 그대로 통과 (풀 이유가 없음) |

## 규칙 종류와 권한

| 규칙 | 누가 만들 수 있나 | HTTPS 필터에서 |
|---|---|---|
| 숨기기 (`##`, display:none) | 누구나 (커뮤니티 팩 포함) | 적용 |
| 스타일 바꾸기, 요소 추가 | 내 폰에서 내가 만든 규칙만 | 적용 (공유 팩에서는 거부) |
| 스크립트, 데이터 고치기 | **해치 공식 코드만** (앱에 고정) | 적용 |
| 은행·결제·정부 사이트 | — | 아무것도 적용 안 함 |

## 보안 원칙

1. **CA 열쇠는 폰에서 새로 만들고 Android Keystore에 "꺼낼 수 없음"으로 보관.** 해치 자신도 열쇠를 읽지 못하고 서명만 요청할 수 있음. 폰마다 다른 열쇠.
2. **사이트용 인증서(leaf)는 메모리에서만** 만들고 저장하지 않음. 앱이 꺼지면 사라짐.
3. **실제 사이트 인증서는 시스템 신뢰 목록으로 엄격히 검사** (호스트 이름 포함). 이상하면 연결 끊음 — 중간자에게 해치가 속지 않게.
4. **풀 사이트 최소화** (위 표). 은행·결제는 목록에 있으면 무조건 통과.
5. **해치를 끄면 중계기도 멈춤.** 인증서는 설정에 남으므로 "인증서 지우는 법"을 앱에서 안내.
6. 통신 위치는 README "네트워크 호출 위치"에 계속 적음.

## 사용자 화면

- 메인: **HTTPS 필터** 카드 (스위치, 인증서 상태, "인증서 설치하기" 안내)
- 인증서 설치 안내: 안드로이드 11부터는 앱이 대신 설치 못 함 → 인증서 파일을 저장하고 설정 화면을 열어 주고 단계별 안내
- **풀고 있는 사이트 / 안 푸는 사이트** 목록 (사이트별 켜고 끄기)
- 상단 "네트워크가 모니터링될 수 있음" 알림은 안드로이드가 띄움(끌 수 없음) → 미리 설명

## 단계

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| **1** | CA 만들기(Keystore) + 인증서 파일 내보내기 + 설치 안내 화면 | 에뮬레이터 설정에 인증서 설치, 크롬이 신뢰하는지 |
| **2** | 중계기에서 TLS 풀기 (고른 사이트만), HTTP/1.1 중계, 실제 사이트 인증서 검사 | 크롬으로 example.com을 풀어서 정상 표시 |
| **3** | 페이지 고치기: 해치 숨김 규칙을 `<style>`로 넣기 | 네이버 팩이 크롬에서 동작 |
| **4** | 유튜브 광고 데이터 지우기 (`adPlacements`, `playerAds` 등) | m.youtube.com 영상에서 광고 없이 재생 |
| **5** | 안 풀 사이트 기본 목록, 실패 자동 통과, 사이트 목록 화면 | 은행 사이트가 그대로 통과 |
| **6** | 내가 만든 규칙의 스타일·추가 허용, 커뮤니티 팩은 숨기기만 | 규칙 종류 검사 |

## 열린 문제

- 크롬/삼성 인터넷이 사용자 인증서를 계속 믿는지 (현재는 믿음, 정책 변경 가능성)
- 유튜브는 광고 데이터 형식을 자주 바꿈 → 공식 코드 업데이트 필요
- HTTP/2를 안 쓰므로 일부 사이트가 느려질 수 있음
